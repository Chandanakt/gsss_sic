1) How floating point numbers are stored using IEEE standards?

-->  Floating-point numbers, as defined by the IEEE 754 standard, are stored in a format that represents a number using three main components: a sign bit, an exponent, and a significand (also known as the mantissa). This is analogous to scientific notation, but in binary. The number is calculated using the formula:


(−1)**8×c×b**q
 

Where:

s is the sign bit.
c is the significand.
b is the base (typically 2 for binary).
q is the exponent

4) Why in Python we do not have increment and decrement?

--> We do not have ++ and -- increment/decrement operators in Python because they can lead to ambiguous and hard-to-read code. Python's design philosophy prioritizes explicitness, simplicity, and readability.

Instead of a single-character shorthand, Python uses compound assignment operators like += 1 and -= 1, which are clearer and do exactly what they say. This approach also aligns with how integers are handled in Python as immutable objects, meaning that an operation like x += 1 creates a new integer object rather than modifying the original one in place.

5) About __main___ 

--> __main__ is a special variable in Python that holds the name of the current scope. When a Python file is run directly, its __name__ variable is automatically set to '__main__'. This allows a common conditional block, if __name__ == "__main__":, to be used to execute code only when the script is the main program, not when it's imported as a module by another script. This is crucial for creating reusable modules and organizing code.

7) Can we modify a list which is an element in tuple ?

--> Yes, we can modify a list that is an element inside a tuple.

This is possible because while a tuple is immutable (meaning you cannot add, remove, or replace its elements), the objects it contains are not necessarily immutable themselves. A tuple only stores references to its elements. The list inside the tuple is a mutable object, and its contents can be changed even though the tuple's structure itself cannot.

This practice allows a program to know its own name, which can be useful for various purposes, such as printing usage instructions or error messages.

9) Why in python there is no implicit typecasting?

--> Python avoids implicit typecasting to prevent unexpected behavior and maintain code clarity. The language's philosophy of "explicit is better than implicit" means programmers must manually convert data types, making the code's intent obvious. This helps prevent subtle bugs that can arise from automatic conversions, such as adding a number to a string and getting an error instead of an unpredictable result

10) Good examples and bad examples of list

--> Good Examples:
Good examples of lists are readable, efficient, and consistent.

List Comprehensions: These are a concise and fast way to create a new list. For example, squares = [x**2 for x in range(5)] creates a list of squares more efficiently than a traditional for loop.

Consistent Data Types: Storing elements of the same type, like a list of strings names = ["Alice", "Bob"], makes your code predictable and prevents errors.

Meaningful Names: Using descriptive variable names like student_scores helps others (and your future self) understand the code's purpose.

Bad Examples: 
Bad examples are unclear, inefficient, or misuse the data structure.

Mixed Data Types: A list with different data types, like data = [1, "apple", True], makes the code confusing and hard to manage.

Inefficient Operations: Using a list as a queue and relying on pop(0) is slow for large lists because it requires re-indexing every element. A deque from the collections module is a better choice for this.

Misusing for Complex Data: Storing structured data in nested lists, such as person = ["John", 30], is a bad practice. A dictionary, like person = {"name": "John", "age": 30}, is much clearer and more accessible.

11) List methods

--> Modifying Methods
These methods change the list in place.

append(element): Adds a single element to the end of the list.

extend(iterable): Adds all elements from an iterable (like another list, tuple, or string) to the end of the list.

insert(index, element): Inserts an element at a specified index.

remove(value): Removes the first occurrence of a given value from the list. It raises a ValueError if the value is not found.

pop([index]): Removes and returns the element at a specified index. If no index is given, it removes and returns the last element.

clear(): Removes all elements from the list, making it empty.

reverse(): Reverses the order of the elements in the list in place.

sort(key=None, reverse=False): Sorts the list in place. You can use optional arguments to customize the sorting order.

Accessing & Counting Methods
These methods do not modify the list.

index(value, [start, end]): Returns the index of the first occurrence of a value. You can specify a range to search within. It raises a ValueError if the value is not found.

count(value): Returns the number of times a value appears in the list.

copy(): Returns a shallow copy of the list. This creates a new list object with the same elements, so changes to the new list don't affect the original.
